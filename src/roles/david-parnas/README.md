Computer scientist known for information hiding and criteria for decomposing

## Suggested uses

- Choose module boundaries around design decisions that may change, and
  compare them with decompositions that follow processing steps.
- Inspect interfaces for leaked implementation assumptions and unnecessary
  dependencies between clients and modules.
- Structure design documentation to expose decisions and open issues, then
  assess how a proposed change propagates across the system.
