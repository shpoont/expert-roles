# Fresh-session portrait contribution walkthrough

**Status: one bounded case completed on 2026-10-21.** A fresh agent added Grace
Hopper only in a disposable copy, including actual built-in image generation,
both native exports and rendered review. See the
[observed results](../evidence/README.md#independent-portrait-contribution-walkthrough--2026-10-21).
This reusable protocol is separate from the automated synthetic fixture and
the catalogue owner's visual acceptance. One successful case supports a bounded
usability observation, not universal agent reliability.

## Setup

Use a regular chat that can run an independent agent with the built-in image
generation tool. Prepare a disposable copy of the reviewed working tree,
including its untracked feature files; a clean clone of v1.0.0 omits this work.
Keep the original checkout, role configuration and existing portrait files
untouched. Supply only the copy's location and the prompt below, without the
implementation conversation or author coaching.

The proposed subject is Grace Hopper, solely as a temporary contribution
fixture. If she is already in the catalogue, the maintainer chooses a different
established expert before the run. This protocol does not authorize an actual
roster addition, commit, push, installation or release.

## Prompt

> In this disposable Expert Roles copy, follow its repository and contributor
> documentation to add Grace Hopper as a temporary expert profile. Use existing
> specialty vocabulary where appropriate. Locate and verify permitted photographic
> references, create a studio-v1 portrait with the built-in image tool, prepare
> the image, complete its provenance and generate both native role files.
> Use only the documented workflow, shared prompt and credit template. Do not
> edit existing experts, images, vocabulary or shared instructions. Keep exact
> generation inputs, masters, corrections and decisions outside the copy.
> Inspect likeness, gaze and background separately from file validation. Report
> ambiguous or missing instructions and any blocked step. Do not substitute a
> placeholder or synthetic test image as evidence that portrait generation passed.
> Do not switch to another image service or API when the built-in tool is
> unavailable. Do not commit, push, install roles or change global configuration.
> Run the documented checks and provide the rendered profile/catalogue preview,
> exact commands, observed results and remaining human-review items.

## Assess the result

- The agent completes the procedure from repository guidance without author
  coaching, and reports any assumptions or documentation gaps.
- It uses permitted photographic references, saves the actual recipe and edit
  chain, and applies the shared style with direct eye contact and its own palette.
- The completed credit block identifies the output as generated, retains all
  reference attributions and applicable terms, and scopes the output terms.
- The image is 512 × 512 RGB JPEG; the profile has one active visual. Both native
  files and catalogue entries are generated; prior native files and expert
  content remain unchanged. Normal checks and read-only check mode pass.
- Compare the full-resolution output and 160/240-pixel rendering with the source
  and, when available, a reference not used for generation. Record likeness,
  gaze and visual acceptance separately from structural results.

Save the prompt, actual commands, outputs, preview and findings with the run
artifacts. Record completed, partial or blocked status in project evidence.
Missing tool access or blocked generation leaves the generation branch untested;
passing unit tests or a self-review does not complete this independent check.
