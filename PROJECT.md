# Current project agreement

## Purpose and intended result

Create a public collection of reusable expert perspectives, methods and role
instructions for AI assistants. Contributors should be able to discover the
catalogue and discuss improvements directly. Independent integrations can
consume an identified revision of the collection.

## Scope and expectations

The agreed project boundary includes role content, references, examples,
contribution guidance and suitable checks. The current authorized work is
repository organization and documentation. The catalogue contains no role
definitions. Role schemas, installers, native agent deployment, host-specific
integration and orchestration are outside this step.

- **Delivery acceptance for this step:** apply the connected Project Structure
  records to this library, retain the top-level catalogue and existing decisions,
  check navigation and public suitability, and leave an accurate handover.
- **Outcome success:** a discoverable, useful collection with contributions and
  evidence of role usefulness. Those outcomes are unproven; the relevant tasks,
  criteria and evaluation method still need agreement.
- **Execution constraints:** retain the setup-only scope, public suitability and
  independent library boundary. Do not select a license, create role definitions,
  tag a release or implement runtime behavior in this step. No additional time or
  budget limits have been agreed.

See the [checks](tests/README.md) and [evidence](evidence/README.md). This alignment
is complete when its documentation and checks are finished; the role-library
project remains open for product design and implementation.

## People and responsibilities

Leon.id Komarovsky owns direction, scope, licensing, acceptance and release
decisions, including permitted exceptions and project closure. Contributors can
propose changes through the [contribution process](CONTRIBUTING.md). Work by an
AI contributor remains within the owner's current authorization. No separate
owner has accepted future outcome-assessment responsibilities yet.

## Assumptions and open questions

Role roster, contents, file format, attribution, evaluation protocol, contribution
terms and licensing remain pending. Host integrations own their own runtime and
packaging decisions. Public source visibility is not a license decision or
evidence of effectiveness.
